## Method (O5 settled: in-process timing)

- Harness: `bench/bench.c`, linked against `liblzmesh.a`, times
  `lzmesh_encode` / `lzmesh_decode` directly with `CLOCK_MONOTONIC`
  (see `bench/README.md` for the O5 rationale). `make bench` runs it.
- Inputs: pinned corpus in `bench/corpus/` (generated by
  `bench/mkcorpus.py`, fixed seeds; sha256 pins in the provenance row).
- Levels: 0, 1, 5, 9 (full-form `0xE00/0xE01/0xE05/0xE09` at the API
  boundary, per `lzmesh.h`), encode and decode separately. Decode input
  is that level's encoded output; the decoder itself is level-free.
- Metrics: throughput in MiB/s (encode over input bytes, decode over
  decoded bytes) and encoded size in bytes. Cells show median with the
  p10–p90 band in parentheses over 35 samples (5 runs × 7 reps).
  Every rep also verifies roundtrip bytes + encode determinism;
  0 failures across the baseline.
- Each run records: date, host, compiler + flags, corpus hash, lane
  commit (provenance row below). No Apple version-specific performance
  claims beyond the recorded oracle runs (none in baseline scope;
  since measured on Air — see the Oracle note below the tables).
- Gated protocol (lane p8-benchharden): all comparisons after the
  baseline go through `bench/run_gated.sh` (`make bench-gated` /
  `make bench-ab`) and are compared with `bench/cmp.py` — load gate
  (refuse at load1 ≥ 2×ncpu, exit 3), P-core pin, interleaved A/B,
  per-run loadavg `#` headers, exact SEPARATED/OVERLAP rule with
  one-doubling-then-NOISE policy. See `bench/GATED-PROTOCOL.md`.
